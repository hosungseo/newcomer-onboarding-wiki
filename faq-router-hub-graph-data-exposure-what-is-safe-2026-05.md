# FAQ — existing hub/router graph exposure: what is safe? (2026-05)

## Short answer

Expose an existing hub/router in graph or data views only when it helps a newcomer choose the next public-only route. Do not expose it as a complete authority map, hidden-data index, or shortcut around source/boundary checks.

## Safe exposure

- Link to [[router-existing-hub-entry-index-2026-05-07]] when the user needs to choose among existing hubs, sections, or low-density route groups.
- Link to [[hub-예산대응]] when the request’s first stable noun is budget, request material, execution, or contract/procurement money flow.
- Link to [[router-정보공개기록관리-협업회의-신규자-공개경계]] when the request mixes disclosure, records, meeting follow-up, and public/non-public boundaries.
- Pair the exposed edge with [[source-graph-data-exposure-existing-hub-router-review-2026-05]] when the question is specifically about graph/data review rather than task execution.

## Unsafe exposure

A graph/data edge is unsafe if it:

1. makes a draft router look like an official complete taxonomy;
2. bypasses the public-only source check;
3. points to a missing or newly invented hub;
4. exposes sensitive categories as searchable destinations rather than stop lines;
5. collapses cross-axis cases into a new hub before [[checklist-router-existing-hub-before-new-hub-2026-05-07]] is run.

## Stop / forbidden lines

- Stop at answering exposure-safety questions; do not update graph exports, docs indexes, README, landing pages, or generated data here.
- Forbidden: commit, push, deletion, rename, placeholder creation, external publication, or edits to existing notes.
- Forbidden: graph exposure of private HR records, personal data, non-public budget strategy, internal deliberation, audit/security details, meeting remarks, legal-advice conclusions, or unverified claims.
