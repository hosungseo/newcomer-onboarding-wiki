# 신규공무원 적응 위키

🌐 **웹 관문**: https://hosungseo.github.io/newcomer-onboarding-wiki/

## 한 줄 정의
공공에 공개된 기관 소개, 법령, 업무계획, 보도자료, 평가자료, 통계를 바탕으로 신입·전입 공무원이 조직과 업무 맥락을 빠르게 익히도록 돕는 **public-data-first onboarding wiki**.

## 바로 시작
처음 들어온 사람은 긴 설명보다 **지금 내 상황에 맞는 첫 경로**가 필요하다. 이 위키는 아래 3개 진입점으로 시작하는 것이 가장 빠르다.

### 1. 상황을 고르며 들어가기
- **관문 페이지**: https://hosungseo.github.io/newcomer-onboarding-wiki/
- 문서처리, 급여, 승진, 복귀, 출장정산, 교육훈련, 재해보상, 민원응대, 정보공개청구, 정부입법, 조달계약, 예산이해처럼 **지금 막 마주친 질문**에서 바로 들어갈 수 있다.
- 전입·인사이동 직후라면 일반 질문을 헤매기보다 **`gate-전입후첫재적응`** 관문에서 시작하는 편이 더 빠르다.
- 특히 지금 필요한 것이 `행안부 축 / 인사혁신처 축 / 기획재정부 축` 중 어느 기관 맥락인지부터 헷갈릴 때 이 gate가 바로 갈라 준다.
- 시스템 쪽도 `e사람 / dBrain / 국민신문고 / 시스템 공통`으로 바로 나뉘기 때문에, 메뉴보다 역할부터 다시 잡고 싶을 때 유용하다.
- 문서처리 쪽도 `내부 문서 흐름 / 대외 응대 흐름 / 문서처리 공통`으로 갈라지므로, 기안·결재가 급한지 민원·정보공개가 급한지에 따라 바로 들어갈 수 있다.
- 인사·복무 쪽도 `휴가 / 유연근무 / 수당·보수 / 근무성적평가·성과관리 / 인사·복무 공통`으로 나뉘기 때문에, 생활 리듬·급여·평가 중 무엇이 먼저 급한지에 따라 바로 내려갈 수 있다.
- 예산·재정 쪽도 `예산 전체 그림 / 편성 기준 / dBrain 실무 / 예산 공통`으로 갈라지므로, 큰 구조를 먼저 잡을지 편성 기준이나 시스템 실무부터 볼지 바로 고를 수 있다.
- 특히 `뭘 모르는지부터 모르겠다` 상태라면 README보다 관문이 더 빠르다.

## 처음 30분 추천 경로
처음 30분에는 위키 전체를 보려 하지 말고 아래 순서로 좁혀 들어가는 편이 낫다.

1. **관문 페이지**에서 지금 상황과 가장 가까운 질문 1개를 고른다.
2. 거기서 나온 **FAQ 1개**를 먼저 읽어 전체 구조를 잡는다.
3. 이어지는 **path note 1개**로 순서를 본다.
4. 그래도 헷갈리면 마지막에 **hub note**로 올라가 기관·기능 연결축을 확인한다.

전입자라면 예외적으로,
- **가장 빠른 시작점은 `gate-전입후첫재적응`** 이고, 이 gate 안에서 먼저 `행정안전부 / 인사혁신처 / 기획재정부 / 기관 공통`, `e사람 / dBrain / 국민신문고 / 시스템 공통`, `내부 문서 흐름 / 대외 응대 흐름 / 문서처리 공통`, `휴가 / 유연근무 / 수당·보수 / 평가 / 인사·복무 공통`, `예산 전체 그림 / 편성 기준 / dBrain 실무 / 예산 공통` 같은 갈래를 고를 수 있다.
- 더 선형으로 읽고 싶다면 `[[faq-전입자의-첫적응질문]]` → `[[newcomer-path-전입후첫재적응질문-2026-05]]` → `[[newcomer-path-전입후첫문서민원질문-2026-05]]` 또는 `[[newcomer-path-전입후첫인사복무질문-2026-05]]` 또는 `[[newcomer-path-전입후첫예산재정질문-2026-05]]` → `[[process-전입후-첫주-재적응]]` → 소속 기관 `hub`

## 왜 이 프로젝트가 필요한가
- 공개 자료는 많지만 흩어져 있어 처음 들어온 사람이 읽기 어렵다.
- 신입은 문서 제목보다 **무엇을 먼저 읽어야 하는지**가 더 필요하다.
- 전입자는 규정은 찾아도 실제 정책 맥락과 용어 체계를 이해하는 데 시간이 걸린다.
- 기관 소개 자료는 있어도, 신규 적응 관점에서 다시 엮인 지식층은 거의 없다.

## 해결하려는 핵심 질문
1. 이 부처는 정부조직법상 무슨 일을 맡는가?
2. 어떤 국·실·과가 어떤 기능을 맡는가?
3. 신규자가 공통으로 먼저 배워야 할 예산·조직·인사·법제·계약 문서는 무엇인가?
4. 어떤 법령과 계획 문서를 먼저 읽어야 하는가?
5. 최근 이 기관이 반복적으로 다루는 현안은 무엇인가?
6. 신규 직원이 첫 주/첫 달에 어떤 순서로 이해하면 좋은가?

## 대상 사용자
- 신규 임용 공무원
- 타 부처·타 기관에서 전입한 공무원
- 수습/인턴/청년인턴
- 교육담당자, 멘토, 인사·운영 부서

## 비목표
- 비공개 내부자료를 다루지 않는다.
- 개인별 업무평가나 인사판단을 하지 않는다.
- 법률 자문이나 최종 정책판단을 대신하지 않는다.
- 내부 메신저/구두 암묵지까지 완전 대체하려 하지 않는다.

## 위키 정보 구조
### A. Source note
원문 1개를 읽고 핵심 사실, 날짜, 기관, 근거 링크를 정리한 기본 노트.
기본값은 여기서 멈추지 않고, 이후 `section / process / concept` 단위로 다시 쪼개는 것이다.

### A-1. Section / topic note
문서 안의 주제 덩어리를 분리한 note.
예: 예산, 인사제도, 입법절차, 보고서 작성, AI 활용.

### A-2. Process / step note
절차 문서의 단계별 note.
예: 입법예고, 관계기관 협의, 검사·검수, 대금지급.

### A-3. Concept / tool note
반복적으로 등장하는 제도·시스템·용어 note.
예: e사람, dBrain, 국민신문고, 예정가격.

### B. 기관 note
해당 부처/기관의 역할, 조직, 최근 현안, 주요 문서 진입점을 묶는 허브 노트.

### C. 기능 note
예: 조직관리, 인사, 복무, 예산, 법제, 계약·조달, 행정운영 같은 공통 기능 중심 노트.

### D. 제도 note
특정 법령·제도·정책수단의 핵심 구조와 실무상 쟁점을 설명하는 노트.

### E. 온보딩 path note
- 30분 이해 코스
- 첫 주 읽기 코스
- 첫 달 적응 코스
처럼 신규 직원 관점에서 재배열한 경로 노트.
기본값은 계급/직급 분기보다 `공통 실무 주제`와 `적응 시점` 기준 재조합이다.

### F. 용어/약어/glossary note
부처 특유의 약어, 회의체, 관행적 표현, 자주 나오는 정책 용어 정리.

### G. FAQ / canonical answer note
반복 질문에 대해 source-backed 답변을 제공하는 노트.

- 문장보다 구조 우선
- 요약만 하지 말고 cross-link 만들기
- 질문에서 반복되는 답은 canonical note로 승격
- 최신성 표기 필수
- 사실 / 해석 / 추천을 구분
- 정부조직법을 기관 역할의 기준선으로 사용
- 기본 작성 단위는 **aggressive practical atomization**
- 큰 요약문보다 **질의 가능한 작은 note network**를 우선

## 기본 파이프라인
1. 공개 자료 수집
2. document-level source note 생성
3. section / process / concept 단위 atomic note 분해
4. 기관 note / 기능 note / 제도 note / FAQ 갱신
5. newcomer path 자동/반자동 생성
6. lint: 중복, 누락, stale claim 점검
7. publish: 읽기 쉬운 정적 위키로 노출

## MVP 범위
### 권장 기본안
**한 개 부처보다 공통 업무 코어 세트로 시작한다.**

기본 추천은 아래 4축이다.
- **행정안전부** — 조직 / 행정운영 / 문서 / 행정관리
- **인사혁신처** — 인사 / 복무
- **최근 10년의 기획재정부 + 분리 이후 기획예산처** — 기획 / 예산 / 재정
- **법제처** — 법제 / 입법 / 법령해석
- **계약·조달 공통 자료군** — 계약 / 조달 / 집행

이유:
- 신규 공무원이 어느 부처에 가더라도 먼저 익혀야 하는 공통 업무축에 가깝다.
- 특히 계약·조달은 정책 전문성보다 먼저 실무 절차로 마주칠 가능성이 높다.
- 정부조직법상 역할 정의와 실제 운영 자료를 함께 엮기 좋다.
- 기관별 정책 전문성보다 먼저 필요한 적응 정보를 제공할 수 있다.
- 이후 개별 부처로 확장할 때도 공통 백본으로 재사용할 수 있다.

### MVP 산출물
- 공통 업무 코어 허브 1개
- 역할축 note 5~7개
- 제도 노트 10개 내외
- glossary 1개
- newcomer path 3개
- source note 40~60개
- FAQ 20개 내외

## 성공 기준
- 신규 직원의 첫 질문 50개 중 다수에 출처 기반 답이 가능할 것
- 기관 이해를 위한 첫 읽기 목록이 10개 이하로 압축될 것
- 각 답변에 근거 source가 연결될 것
- 최근 3개월 내 자료가 위키에 반영될 것
- 실제 사용자가 '무엇을 먼저 봐야 할지 모르겠다'는 상태에서 벗어날 것

## 주요 리스크
### 1. 공개자료만으로는 맥락이 부족할 수 있음
대응: 내부 암묵지 흉내를 내지 말고, 공개자료 기반 맥락 정리 도구로 포지셔닝.

### 2. 문서가 너무 많아 초기 구축 비용이 커질 수 있음
대응: 공통 업무 코어 4축을 먼저 채우고, 이후 개별 부처로 확장.

### 3. 오래된 조직도/업무자료가 섞일 수 있음
대응: 최신성 배지와 기준일 표기.

### 4. LLM이 기관 기능을 과잉 일반화할 수 있음
대응: 모든 설명에 source note 연결, lint 단계에서 검토.

## 걱정 포인트 / 막힐 수 있는 지점 / 대안
- 걱정 포인트: 공개자료만으로 신규 적응에 충분한 밀도를 만들 수 있는가
- 막힐 수 있는 지점: 자료 품질 편차, 조직도 변경, 부처별 문체 차이
- 대안: 공통 업무 코어 → 사용자 질문 수집 → note 구조 보완
