# Source — graph/data exposure review for existing hub/router notes (2026-05)

## Claim

Graph/data exposure is acceptable only when the visible edge preserves an existing-entry decision path: first choose an existing hub/router, then verify the public-only boundary, then stop before creating or implying a new hub.

## Existing anchors

- [[router-existing-hub-entry-index-2026-05-07]] — keeps newcomer routing anchored to existing root entries before new hub creation.
- [[hub-예산대응]] — shows a public-only hub pattern with source/process/checklist descent and explicit non-public exclusions.
- [[router-정보공개기록관리-협업회의-신규자-공개경계]] — shows a router pattern that separates public source material from internal review, meeting remarks, and sensitive records.
- [[checklist-router-existing-hub-before-new-hub-2026-05-07]] — blocks graph/data promotion when the route would duplicate or invent a hub.

## Exposure review test

1. The graph edge must point to an already-existing root note, not a planned placeholder.
2. The exposed label must say “entry”, “router”, “source”, “checklist”, or “boundary”; avoid labels that imply official completeness.
3. The path must include at least one public-only boundary note before any README, landing, catalog, or data export surface uses it.
4. If the same request can enter both a hub and a router, keep the first stable noun rule from [[router-existing-hub-entry-index-2026-05-07]] rather than adding a new surface node.

## Stop / forbidden lines

- Stop at reviewing graph/data exposure; do not edit README, landing pages, generated graph data, catalogs, or dashboards in this lane.
- Forbidden: creating placeholder destinations, broad renames, deleting or moving notes, commit, push, or modifying existing root notes.
- Forbidden: exposing private HR facts, non-public budget strategy, internal deliberation, meeting remarks, personal data, legal-advice conclusions, or unverified source claims.
