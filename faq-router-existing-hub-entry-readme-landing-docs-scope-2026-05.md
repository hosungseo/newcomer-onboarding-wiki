# FAQ — router existing hub entry: README/landing/docs scope (2026-05)

## Question

When should [[router-existing-hub-entry-index-2026-05-07]] be exposed from README, landing, or docs surfaces?

## Answer

Expose this router only when the surface is helping a newcomer choose an existing entry before creating a new hub. The target route is not a general catalog item; it is a guardrail for first-entry selection.

Use it when the surrounding page already points readers toward one of these stable anchors:

- [[process-existing-hub-entry-decision-2026-05-07]] for first-stable-noun selection.
- [[checklist-router-existing-hub-before-new-hub-2026-05-07]] for the "do not create a duplicate hub yet" gate.
- [[section-low-density-hub-path-exposure-2026-05-07]] for low-density axes that are exposed as grouped routes.
- [[coverage-low-density-hub-path-exposure-2026-05-07]] when the page needs exposure evidence rather than another route.

The smallest safe README/landing/docs sentence is:

> Before adding a hub, use [[router-existing-hub-entry-index-2026-05-07]] to choose an existing hub or low-density section route, then run [[checklist-router-existing-hub-before-new-hub-2026-05-07]].

## Stop / forbidden lines

- Stop if the page needs a new destination note; this FAQ only explains exposure scope.
- Stop if the router would be presented as a complete onboarding map instead of a pre-hub decision guardrail.
- Forbidden in this lane: editing README.md, landing files, docs index, generated catalogs, graph/data files, existing hubs, commits, pushes, deletion, renaming, or broad refactor.
- Forbidden in this lane: linking to missing wikilinks or creating placeholder hub pages.
