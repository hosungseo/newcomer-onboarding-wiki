# FAQ — existing hub entry: why not create a new hub? (2026-05)

## Question

When a newcomer question touches 예산, 인사, 기관/기능, or a low-density exposed axis, why should the router-existing-hub-entry-index lane prefer an existing hub or section checkpoint instead of creating a new hub?

## Answer

Create no new hub when the question can already enter through a stable root surface. Use [[checklist-existing-hub-entry-decision-2026-05-07]] to confirm the candidate entry exists, then use [[process-existing-hub-entry-decision-2026-05-07]] to choose the first route by the user's first stable noun.

The practical rule is simple:

- 기관, 부서, 기능, unfamiliar portfolio → [[hub-기관또는기능]]
- budget request, execution, contract/procurement money flow, or budget-facing material → [[hub-예산대응]]
- appointment, transfer, leave, promotion, training, e사람, personnel record, or HR calculation → [[hub-인사]]
- low-density axes already grouped for exposure → [[section-low-density-hub-path-exposure-2026-05-07]]

This keeps the router-existing-hub-entry-index supporting layer atomic: it explains entry selection without expanding hubs, catalogs, landing pages, or graph surfaces.

## Stop / forbidden lines

- Stop if any selected entry is not an existing root markdown note.
- Stop if the request needs private data, internal strategy, non-public deliberation, personal HR facts, or legal-advice conclusions.
- Forbidden in this lane: creating a duplicate hub for an axis that already has an adequate route.
- Forbidden in this lane: editing existing hubs, README.md, docs/index.html, landing files, graph/data files, generated catalogs, commit, push, deletion, renaming, or broad refactor.
